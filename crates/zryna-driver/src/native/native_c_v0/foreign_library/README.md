# Retained foreign object boundary (#417)

This module captures one static ELF64 little-endian x86-64 relocatable object
against the genuine original source/IR/MIR/object authority. It preserves the
exact versioned library, header, operation policy and selected program object.
The independently supplied expected object size/hash and dependency inventory
are checked against actual immutable bytes. They are caller-supplied identity
prerequisites, **not authenticated approval or recipe execution authority**.
Changing both bytes and their expected hash can capture different data. It
cannot grant a host capability, cache write, publication or public native route.

The closed inventory checks every declared imported function in the library,
including functions unselected by the current program. It rejects extra global
definitions, weak/common/IFUNC symbols, reserved private runtime names,
constructor/TLS/dynamic sections and unsupported relocation fields or targets.
Raw header/table validation precedes the generic object iterators so malformed
links or truncated relocation arrays cannot silently disappear from the audit.
The accepted subset has at most 16 non-null sections, 4,096 non-null symbols,
32,768 relocations, 64 dependencies, and the existing 8 MiB object/storage limit.
Dependencies are exact sorted unique C identifiers of at most 128 bytes.
This is a deliberately narrow GCC non-PIC object subset, not an archive, shared
library, loader-search or general ELF interface.

The Linux x86-64 tests compile an independently authored seven-operation C
fixture **separately** from the compiler-generated object and observation client.
They use retained capability-relative staging and bounded existing process
helpers. They prove snapshot use after acquired-path replacement, scalar wrap,
reverse cleanup of every accepted two-handle allocation prefix, actual symbol
substitution rejection, and cleanup/retry after an actual unresolved-symbol
link failure. A structurally accepted fixture that calls `abort()` produces
SIGABRT: structural capture cannot establish the safety of a C body or promise
recoverable status, in-process containment or cleanup after a crash.
The test-only foreign object recipe explicitly selects `-fcf-protection=none`
for this closed fixture subset. An independent `-fcf-protection=full` control
emits GNU property metadata and remains rejected. These fixture arguments do
not select or authorize a production recipe's compiler or security policy.

The byte proof additionally compiles the original issuer's private runtime in
a separate translation unit, includes its retained ABI header, and links it
with the generated object, captured foreign object and independent client.
Malloc/free observations verify distinct private copies at lengths 0, 3 and
4096, each allocation-failure point, a mixed handle/byte reverse cleanup prefix,
and controlled malformed metadata. An actual missing-release C mutant fails
the physical owner oracle; the pristine implementation then passes again.
The C library, runtime and client also run with ASan/UBSan. Instrumented objects
remain rejected by production capture; the generated machine code is not
instrumented, and these observations do not establish arbitrary C body safety.

Separate-object regression definitions also require the complete valid/invalid UTF-8
corpus to cross a direct client-owned `--wrap=sum_bytes` call counter. Valid calls
increment it once, corruption leaves it zero, and a missing-increment counter mutant
must fail before receiving no-entry credit. The seven-definition C fixture remains
unchanged; zero malloc/free counts do not demonstrate zero calls. Ordinary and
sanitizer links select this fixed instrumentation only for the new UTF-8 tests.

Error-status output-write derivatives retain the seven strong definitions and original
operation policy; actual output bytes and unknown obligations grant no guessed release.
Their physical oracle's explicit disposal remains separate from generated cleanup.
The release-fault derivative declares `_Exit` and a client-owned release observer as
additional exact dependencies. The observer checks the live ledger, physical C owner
and pending private allocations before exit 86; an early non-null output-channel mutant
must fail the same assertion. This client-only sensitivity control publishes the
initialized private copy's actual data pointer with length and capacity three;
generated machine code remains unchanged. A new pristine process
proves stage recovery, not cleanup of a terminated foreign owner. These test definitions
are not production library approval or host-isolation/recipe admission.

`tests/execution/bytes/reference-provenance.json` records the exact existing
fixture body, normative header/policy and private-runtime template at preserved
checkpoint `42f8e80`. Local proof logs record the actual compiled object and
rendered source digests. These are reviewed fixture prerequisites with no
production approval. Controlled hostile derivatives are identified by their
actual source digest; they are not approved library bodies. The separate SQLite
and Rust-shim fixtures retain their own source and operation policies. Neither
issues an authentic #405 host-admission capability. The normative stage order
requires the audited raw boundary and library-specific ownership policy before
those proofs.

## Full-feature acceptance still open

`linked_output/` is a Linux x86-64 test-only compile/link observation producer. Its two
fixture consumers retain genuine original requirements and captured-library capabilities,
actual foreign/client/private-runtime objects and sources, the originating GCC/linker
capability for every invocation, exact arguments and outputs, final ELF bytes, and the
linker's observed input order including repeated archive occurrences. The private runtime
producer preserves the original rendered-source/header binding. Client objects are compiled
separately using the existing fixture client warning policy; foreign/runtime compilation
retains strict warnings. No shared staging allowlist or production recipe guard changes.
The observer's uninstrumented fixture profile explicitly selects `-fno-stack-protector`
so distribution GCC defaults cannot add an undeclared runtime dependency. An actual
`-fstack-protector-all` compiler control still rejects `__stack_chk_fail`; the audit's
exact four-import inventory is unchanged. This selects no production security policy.

The observer returns before driver executable permissions or target execution and grants no
execution, cache or publication capability. GCC itself may create executable file modes.
After stage cleanup, a create-only private evidence export can retain the actual artifacts;
`ZRYNA_LINKED_OUTPUT_EVIDENCE_DIR` selects an existing external parent for the scalar/byte
test exports. Without it, each test uses its disposable fixture root. Failure records retain
actual invocation status/stdout/stderr. Successful-link audit failures additionally keep the
bounded raw final ELF and actual program/foreign/client/private-runtime object and source bytes
through cleanup, with the exact comparator stage. A create-only `failed-scalar` or `failed-byte`
export under the configured evidence parent writes these bytes and the failure receipt before
its test reports failure. No failed artifact is qualification or executable authority.
Existing execution and sanitizer paths remain separate.

The legacy observer retains PT_INTERP, DT_NEEDED, RPATH/RUNPATH, dynamic entries and GNU
version sections as requirements. The optional private comparison below checks a separately
issued selected material inventory and declared provider graph. Neither mode supplies an
approved production provider inventory. Trace output is not complete input-use attestation.
The unchanged limited executable audit still applies. Production ordered inputs, authoritative
loader/provider/load-search policy and recipe/host admission remain explicitly missing.
Source or output hashes cannot issue those authorities. No other PR's toolchain or sanitizer
runtime policy is borrowed.

## Independently pinned private inventory comparison

`linked_output/acquisition.rs` owns closed expectation parsing, original source/library binding,
selected byte snapshots and data reporting. Its `files.rs` walks canonical ancestors with
owned directory descriptors, rejects links and nonregular leaves without blocking on FIFOs,
and checks before/open/after identities. `inventory.rs` validates names, case/parent conflicts,
role-specific bounds and the exact ordered trace slots. `observed.rs` compares the actual
producer-bound object path aliases and final ELF. `postlink.rs` owns bounded final-byte retention,
limited native/legacy metadata checks and the optional declared inventory comparison. The
producer keeps compiler/link invocation ownership and cleanup attribution. The byte consumer checks retained inputs
against the originating tool capability before any new private-runtime compile. A test-only
thread-local invocation-attempt counter starts its control after the prior foreign prerequisite;
the real independently pinned hostile-role control preserves bytes while changing only the
driver/linker Tool roles and proves no new runtime, client or link attempt. The separately owned `closure/` modules
parse the declared ELF64 little-endian x86-64 ET_DYN providers and ET_EXEC result, dynamic
tags, symbol kinds, GNU version definitions/requirements, and the exact direct/transitive
SONAME graph. Unknown or malformed constructs reject; no loader search or resolver executes.

A qualified private fixture must supply `observe_with_inventory` an opaque retained input
request. The original `observe` interface remains an unqualified compile/link observation.
The scalar and byte consumers accept the exact external expectation path and raw SHA-256 via
`ZRYNA_LINK_INVENTORY_EXPECTATION_FILE` and `ZRYNA_LINK_INVENTORY_EXPECTATION_SHA256`.
Both absent means legacy observation only; partial configuration, malformed input or a wrong
pin rejects. Positive qualification runs must set both and assert the report's
`inventory_qualification_requested` field and non-null comparison records. The selected test
names are `linked_observation_retains_real_scalar_objects_and_never_runs_client` and
`linked_observation_retains_original_byte_runtime_without_executing_it`. Their explicit
`m5-private-scalar-inventory-qualified` / `m5-private-byte-inventory-qualified` records are
separate from the legacy `not-requested` records.

The private `zryna.private-link-inventory.v1` manifest supplies target, canonical copied root,
selected material IDs/roles/relative paths/exact lengths/SHA-256, canonical `original_path`
and optional linker `trace_path`, an ordered slot list and a closed provider expectation.
The trace path may retain an independently observed spelling such as a toolchain `../` alias;
it is never treated as canonical byte identity. Object slots (`client`, `program`, `foreign`,
`runtime`) come from the actual producer stages. `material:<id>` and `member:<id>:<member>`
slots preserve every repeated archive occurrence, rather than reducing the trace to a set.
Tools have a 64 MiB per-file private capture bound; other materials retain the existing 32 MiB
native executable bound. At most 64 selected files and 128 MiB of retained material bytes are
allowed, including at most eight Tool entries. Provider snapshots share those immutable buffers. The manifest itself retains the
existing bounded native tool-output limit. These are private data limits, not runtime grants.

Independent expected hashes must exist before capture. Capture validates the declared retained
provider graph before any newly affected observer compile/link process. Original tool paths
must also agree with the originating discovered tool capability. All selected original paths
are compared with their retained snapshots before and after the newly affected client/link
processes. This is an ordinary before/after comparison: transient input replacement, compiler
child shared-library dependencies and complete linker IO are not attested. Selected named
files are not a wildcard inventory of the copied directory and are not an interpretation of
the production #361 sysroot digest. Expected hashes or allow-weak/IFUNC/TLS metadata flags
cannot grant execution safety, host isolation, cache writes, publication or native activation.

Create-only exports include each `acquired-<id>.bin` snapshot and the observation receipt,
with comparison data distinct from the unchanged missing-prerequisite denials. Structural
fixtures cover boundaries and rejected mutations without claiming host qualification; actual
scalar/byte qualification needs the independently frozen host inputs and real processes.

## Distinct Rust-profile artifact data

The public data-only `RustProfileLibraryInput`, `CapturedRustProfileLibrary` and
`capture_rust_profile_library` API is separate from the unchanged GCC-style capture.
A private production parser validates the bounded ELF64 x86-64 function-section
profile of exactly add/sum_bytes and eight sections against genuine original Zryna source/header/policy and independent foreign
source/object expectations. The measured fixture bytes retain `.text.add`,
`.text.sum_bytes`, the combined section/symbol string table and original `.comment`;
no bytes are stripped or rewritten to fit the C profile. Unknown symbols,
relocations, dynamic/TLS/unwind/constructor/writable sections and substituted
original requirements reject. Foreign-source and object bytes each have the
existing 8 MiB prehash/precopy bound. Their combined immutable buffers retain at
most 16 MiB; this is not qualified tool-inventory storage or execution authority.

A capture binds only to its original selected object and source-map/declaration
issuer. A separate genuine issuer may create its own separately bound capture.
The issuer authenticates Zryna source/header/policy only: independently retained
Rust source and ELF bytes do not prove that a compiler produced one from the
other. The type has no execution method or conversion to `CapturedForeignLibrary`
or the GCC-origin `CompiledObject`/`Invocation`. No CLI/profile/guest support,
compilation-origin, host, provider, publication or recipe grant follows.

The registered `rust_abi::profile_tests` use the actual independently observed
1064-byte object as data and genuine scalar/byte issuers. Their source/binding,
malformed-table, closed-symbol, material-substitution, limit and recovery checks
are distinct from Rust compilation, generated-wrapper/reverse execution,
malformed-status/write-on-error and sanitizer qualification. Existing normative
#417 obligations and all production missing-prerequisite denials remain. The
actual 157802496-byte Rust driver exceeds unchanged 64 MiB tool/128 MiB private aggregate
limits; this data API neither omits that dependency nor raises those limits.
