# Structural Struct Clone continuation — design only

No implementation, Cargo, provider process, syntax authentication, new seal or runtime qualification accompanies this proposal. Exact source literals and independent expectations are frozen in SOURCE_EXPECTED_FREEZE.json. The active candidate is unchanged. The accepted #415 packet remains the complete goal; this proposal is one implementation slice, not a new language restriction or full #416 closure.

## Normative source authority

Read spec/language/BOUNDED_GENERICS_OPTION_RESULT_V1.md together with BOUNDED_GENERICS_DECISIONS_V1.md, especially the decisions at lines82–96: opaque bodies cannot assume Clone, nominal Copy/Clone derive from every actual substituted stored member and every possible payload, and a finite graph calculation implements inherited M3 rules. A closed Copy specialization cannot legalize clone(T). Phantom argument affinity is not stored-member affinity. Neither a sealed layout, zero drop_kind nor a successful closed String clone grants source Clone authority.

The current semantic body capability solver already represents separate Copy and Clone capabilities (bounded_generics_v1/body_types/capabilities.rs and containers.rs87–100). Preserve that original-body M7002 owner, operation-keyword span and original-before-discovery order. Do not remap an independent source proof failure into capability admission. Validate actual arguments even when phantom; only stored-member edges contribute to Clone. Opaque atoms remain owner/slot qualified across substitutions. Keep cycle proof and all current work/key/member bounds.

A new private v5 source facade must independently prove a Clone fact in the IR source owner. Derive `(affine, cloneable)` separately: scalar leaves provide Clone; String provides Clone and remains affine; an opaque stored atom provides neither Copy nor Clone; Struct/enum facts combine all actual stored fields/payloads; Option/Result combine every possible payload. Phantom<T>{code:i32} therefore provides Copy/Clone without assuming anything about T, while Fixed<T>{owned:String;code:i32} remains affine but cloneable even when T is opaque and unused. A Box<T> storing opaque T remains unclonable. Source validation of a phantom argument still occurs independently.

Do not change the legacy/v4 source-fact debits to fund this work. A v5-only fact/description route can share pure normalized-term algorithms, but its query/cache identity and complete logical work must be explicit. Preserve completed-root cache cold/hit cost equality and failed-miss rollback. No layout is passed as source capability authority.

## Distinct wire/domain decision

Use a distinct private owned V5 domain, detailed in WIRE_V5_DECISION.md. Preserve generic core-v1 and owned-v2/v3/v4 encodings and rejection behavior. New owned tag10 is `CloneStruct { value:u32 }`, admitted only under v5. It replaces an exact Unit placeholder whose result has the exact same closed Struct type as the stored source operand. No caller-supplied recipe, initialized count, field path, Clone flag or arbitrary runtime symbol enters the wire.

There is no existing EnumClone opcode to broaden. Current source/clones.rs expands six exact standard-family keys into borrowed-match CFG plus old tag7 `CloneBorrowedString`. Tag7 remains an exact live shared Borrow<String> leaf; tag6 remains exact stored String clone; tags8/9 retain their v4 construction/Copy-field meanings. Never reinterpret any of these as Struct clone.

V5 decode returns its own opaque untrusted carrier. Only a typed owning issuer selects internal StructClone admission, after full syntax/source/original capability/demand/dual-layout/runtime/type/plan/ABI checks. No raw mode bit or old decoded-wrapper conversion is added. Existing v4 source entrypoints keep their prior source and opcode admission. Existing non-Clone v4 artifact bytes and resource oracles remain pinned.

## Whole-value operation and cleanup

`clone(namedStoredStruct)` reads a complete live Struct without consuming it and produces a distinct same-type result. A surrounding shared loan may remain live. A moved root or active exclusive loan rejects. The initial source operation does not introduce field subloans, partial field moves or clone(Borrow<Struct>) as an incidental side effect. Borrowed-payload Clone required by the full accepted contract remains an explicit later source/IR gate if it is not implemented with this slice.

Copy Struct roots also provide explicit Clone: they copy exact scalar/Copy lanes with no runtime String allocation. Use the same v5 CloneStruct vocabulary, with independent proof that its recipe has no fallible leaf and hence no failure Step. Do not infer the original capability from the closed zero-drop result.

Construction/clone traversal visits fields in declaration order. Nested Structs recurse; standard/user enum children inspect only their active payload at runtime, although source capability proves all possible payloads. A String leaf invokes the existing stringClone contract once and publishes no result on failure. Every successful String clone has a fresh identity even if bytes match its source. Aggregate carriers remain private non-owning containers/lane groups: this slice adds no carrier allocation, runtime symbol or ABI change.

Before a fallible CloneStruct operation, owner replay snapshots all current loans and pre-existing owners, including the source. The result is absent. The operation does not consume source members; it adds the complete result owner only on success. On failure the clone kernel first unwinds the partial destination child, then completed destination children in reverse, with no release of uninitialized leaves. Only then does the existing operation failure Step end loans and drop pre-existing roots in reverse order. Thus “source retained on failure” means retained throughout preparation/local prefix rollback and then included in ordinary caller failure cleanup; it does not promise a usable source after the enclosing function traps.

No raw partial aggregate becomes an ordinary owner or Step cleanup ID. Derive and retain a private operation-bound Clone recipe/frontier after mandatory IR proof. Bind exact function/result/operand type and site; prove field order, enum ordinals, String leaf roles, complete Copy ranges and prefix topology from authenticated source plus independently sealed layouts. A caller cannot install or mutate it. A backend-private initialized cursor is runtime progress, not a wire claim or source authority. Copy-only destinations never read uninitialized String lanes.

## Existing M3 kernels: reuse with the right authority

The strongest existing protocol model is data_ownership_v1/generic_clone.rs: VerifiedGenericClone and its frontier bind a complete source, unique destination/result, exact prepare/prefix site and recursive destination progress. Its documented traversal unwinds a partial child, completed siblings in reverse and any acquired container storage last. The older ClonePlace String-leaf protocol also proves exact aggregate leaf failure, but explicitly excludes nested Enum/Vec/handle graphs; it is not a general nested-family certificate.

Existing native data_ownership_v1/clone.rs and clone_cleanup.rs, Wasm encode/memory/clone.rs plus clone_frontier.rs, and the JS data-ownership lowering already implement relevant typed traversal, String cloning and prefix cleanup. Reuse effect-free recipe/frontier logic and existing String leaf emission primitives when a private adapter can consume the *correct* opaque source/layout/operation authority. Keep the per-domain issuer and source/owner proof independent.

Directly passing a generic_v1 VerifiedOwnedProgram to an M3 helper is invalid: the authorities and layout domains differ. Native M3 clone_value also uses memory-record allocation/representation, whereas generic owned Structs use flattened lanes and the three-symbol String runtime. Reusing that allocator/helper unchanged would add allocations/ABI meaning and violate the frozen traces. If extracting a shared pure traversal would alter old target artifacts or require accepting raw layout/category DTOs as authority, leave that old kernel intact and reuse only its verified String calls and proven cleanup law through a new checked v5 lane adapter. This is an implementation constraint, not permission to infer Clone from width/drop_kind.

## Fixed proposal and gates

Seven positive literals and five negative literals are frozen before any provider. `nested-prefix` fixes E,L,R,T then cloned L,R,T despite reversed object spelling. `repeat-source` proves repeated clones retain source and allocate distinct leaves; `shared-owner` retains a pre-existing shared loan; `fixed-member` proves stored String drives affinity/Clone despite phantom T; `phantom-opaque` proves actual Copy members permit Clone without assuming T; `family-fields` tests inactive and active Option<String>; `copy-struct` performs no runtime allocation.

The independent primary prefix operation/plan proposal is PREFIX_PLAN_ORACLE.json. The runtime expectations compare identities and release order, not text or live-count totals. Fixed-member success deliberately releases original identity1 in its callee before returned clone identity2 at the caller. Every controlled fault is followed by a pristine success using the same sealed program/artifact. Future obligations total7 successes+21 faults+21 retries=49 observations per target,147 across JS/Wasm/Linux, including21 native controlled fault processes. These are unexecuted obligations, not a recorded count.

First authenticate all complete provider packets against the exact frozen source maps; no appended wrapper/export is needed. Then capture genuine semantic/source and old-domain hostile REDs before production. After implementation, independently seal the same v5 claim once per positive and emit all three targets from that retained program. Keep exact wire/artifact identities, target inventory audits and String allocation/release identities. Run old v1/v2/v3/v4 byte/diagnostic/cost regressions, old same-seal cases, flat-wide N7001, wrapped1 success and wrapped24 N7001 unchanged. Typed/raw-map controls alone do not prove source or target execution.

The accepted complete #415 contract also requires remaining arrays, containers, handles, borrowed operations and public driver/version admission. This Struct Clone slice does not close those gates, and the specification must not be edited to match an implementation gap.
