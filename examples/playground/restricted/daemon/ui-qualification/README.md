This is a distinct trusted operator test tool. It is not part of the source-launcher
24-file closure and never grants a network or execution capability to a guest.

Before releasing the capability, each post-proc-audit and post-material-audit
kernel snapshot uses one acquisition window of at most one second within the
original owner deadline, including its Engine inspect. It admits at most three
fresh complete captures. A discarded candidate must prove that exactly one
selected nonleader task ended. The FIRST variant requires exact membership
OPEN/ENOENT and absent stat/status before and after that failed read. The LAST
variant first retains an immutable live epoch/Tgid and membership proof only
after the original FIRST equality check passes. Its final membership read must
fail with exact OPEN/ENOENT; both `targetBefore` and `targetAfter` are then
post-failure stat/status absence samples. Its `priorTask` records the earlier
verified live epoch, rather than claiming absence before the failed LAST read.
Both variants require unchanged original init and leader epochs/membership,
the same cgroup losing exactly that task, and a complete
PPid inventory with no escaped or unreaped owned descendant. The task must remain
absent after that inventory. Every other capture failure is fatal. Every accepted
candidate passes the full original capture guards and retains the pre-audit
CID/PID/start epoch and leader anchors; later candidates cannot adopt a replacement.
The discarded witness forbids added threads. A later fresh candidate observes its
own complete current thread set and must prove every member through all guards.
Typed acquisition
rows preserve the discarded witness and accepted snapshot. The bound never renews
the owner deadline, never applies after capability release, and does not change
the separate cleanup deadline.

Do not treat malformed/truncated engine or application EOF as a result; call
decoder.end(), demux.end(), and session.eof(). `send` must be a bounded serialized
frame writer to attached container stdin, attached before start. Both directions
must retain their aggregate budgets. Do not use a TTY, host tunnel/proxy, host
network, engine socket mount, or generic command transport. The image-pinned
trusted UI adapter binds only tcp4 `127.0.0.1` at the original selectedOrigin port
inside the existing net-none namespace. It validates the actual listener, Host and
local/peer addresses and forwards only fixed routes through stdio. Chromium
therefore creates the real request headers; no Playwright request-stage header
snapshot or synthetic Fetch Metadata is used. The original service/profile stays
unchanged. Socket/body/request bounds and listener-close ownership are explicit.

The broker forwards actual browser request headers only, without inserting missing
Authorization/Origin/Sec-Fetch-Site. It forwards actual response statuses, security
headers and bytes and never invents a compiler/session/evaluation response.
It has a fixed origin and closed route enum, bounded queue/inflight/total requests,
and finite byte/time budgets. Unknown routes, redirects, headers, workers or
noncanonical targets fail. Capability/header/job-token values never enter its
audit records. The caller must preserve this rule when storing raw protocol data;
**do not persist raw stdio, Playwright traces, HAR, console output or launch URLs**.
Transport failures retain a closed event-site code. Browser request failures map
only exact known network-error categories; unrecognized metadata becomes UNKNOWN.
These diagnostics identify the observed boundary and do not establish its cause.
For a failed request, a bounded WeakMap records the exact Request object's ordinal,
closed route/method/type and same-object response/status/finished events. Unseen
objects remain UNKNOWN. The snapshot belongs to that exact network Error; a later
failure cannot attach its metadata to an earlier guard. Ordinals are not host HTTP
IDs, and a response event does not prove that the browser consumed the body.
The driver latches the first observed failure, phase and branch before owned
browser cleanup. A later stream error remains fatal and cannot replace that
earlier cause; finalized cleanup and process observations are retained separately.
The initial compile remains held before host dispatch until both the matching
browser `requestfailed` and actual HTTP response-close are observed. Only its
acknowledged abort, successful `/cancel` and drained initial job admit the single
closed `corpus-begin` transition. Both inner and host fences reject a second
compile or any evaluator dispatch before this transition. Later requests cannot
replace or reset the initial abort proof. Response authentication is awaited before
forwarding bytes to the browser; pending inspections belong to owned cleanup.
