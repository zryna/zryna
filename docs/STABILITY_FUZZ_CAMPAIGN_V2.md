# Bounded existing-generator campaign v2

This preparation does not establish an actual campaign, honest hosted provenance,
public activation or total M7 closure. Receipts retain blocked/global-M7-false
status. Collection requires a newly committed, clean, registered candidate and
its own admitted Linux/Windows observations. The complete original
security-authorities command, including ignored tests and its two-hour limit,
remains mandatory. Finite source/provider/IR/MIR owners are distinct properties;
there is no invented requirement that every boundary have a random generator.

Witnesses retain the original lexer 256×32 and parser 2048×versions 2–4 inputs,
corpora, seeds and budgets. Protocol v2 has one output record per execution,
identified by case, optional version and execution 0/1. Lexer Result originals
are retained before unwrap/expect or any original equality/source/reconstruction
oracle. Every parser raw DTO is retained before the original JSON conversion
and Rust source verifier; rejection JSON precedes later comparisons. Every record
is flushed. Complete is emitted only after all original loops and assertions.
The qualifying lexer has 770 events, including 512 outputs; the parser has 14338,
including 12288 outputs. Failures retain incomplete inputs and completed outcomes,
raw logs and a failure journal, stop further commands and cannot qualify. There
are no retries, replacement inputs or shrinking. Existing source/document/log/
witness/deadline/cleanup limits remain unchanged.

Detached accepted DTO checks bind schema version and the complete one-file set
(id 0 and exact retained path), close top/file/function/parameter/body/block/arena
and diagnostic envelopes, require structural collections, and validate all
retained ranges. They use the existing 256 KiB record, 8192-node and depth 24 limits.
Collections are bounded: functions/imports 4096, parameters 256, blocks/statements 4096,
expressions/type/declaration collections 16384 and diagnostics 256. v2 has inline
types; v3 adds import/block collections; v4 has type indices/declarations. Import,
type and declaration entries must be objects with spans. Numeric fields fit u32.
Diagnostic code/severity/location/text shapes are closed; messages/guidance have
at most 4096 scalars. Source/global locations are checked. Every span requires
file 0, integral 0 <=start<=end<=retained UTF-8 bytes and scalar boundaries; only
protocol-optional export/as/none spans may be null.

These detached checks intentionally do not duplicate all variant payloads,
source spelling ownership, omitted declarations, canonical graph arenas/edges,
dominance or semantic typing. Rust source/graph verification remains an actual
execution observation. Positive controls use unchanged independent frozen DTOs
and original source bytes. Synthetic transcripts and transplants test validator
behavior only and never qualify as actual compiler evidence.

Direct children, synchronous Git inspections and Windows cleanup receive token
filtering that preserves proxy/CA configuration. Windows cleanup uses the same
supplied environment and original literal taskkill/deadline/buffer policy. No
parent-environment token deletion spans an await. Existing process/interruption
guards and new hostile tests must pass before collection; final independent host,
artifact/provenance and threat-model review remain separate authorities.

Provider diagnostic envelopes admit existing TypeScript parse codes (`TS` plus
four or five digits with a nonzero first digit) alongside Zryna diagnostic codes.
Lexer and parser rejection envelopes retain their Zryna-only codes. Windows tool
observation resolves the existing reviewed pnpm shim metadata to the pinned
`pnpm.cjs` entry and launches it through the same Node executable, without a
shell. Collection uses the standard pnpm JS package setup, matching the existing
M4 resolver contract; standalone native-package shims are not JS entries. The receipt retains the actual executable and argv; replay checks those
fields as well as the original version streams. Original failed campaigns remain
failed, including the b22 parser replay rejection and Windows pnpm ENOENT.
