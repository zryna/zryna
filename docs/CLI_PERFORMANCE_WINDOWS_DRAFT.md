# Windows workload collection draft

`captureWindowsDraft({ document, capture, oracles, root, output })` supplies real Windows IO to the finite `collectWindowsRound` controller. Compose these new files with the exact shared V4 dependencies listed in `MAPPING.json`. This packet changes no shared declaration, existing helper, CLI, workload, oracle, CI workflow, baseline or threshold.

The frozen V4 reader supplies exactly 20 Windows cells: four original families, three build targets, and JavaScript/WebAssembly run targets. Each cell has one retained warmup and five measured observations in catalogue order. Every invocation uses the same original entry, CLI argv, output stem, typed oracle and M3 owned `main.zry`/`math.zry` staging. The collector never generates correctness goldens, chooses an observation, retries, deletes an outlier or accepts caller-selected commands.

The capture record format is `zryna.cli-performance-windows-capture.draft.v1`. Required fields are `catalogueSha256`, `round`, `cliBuildClass`, `sourceCommit`, `sourceTree`, `host`, `tools`, `operatorAdmission`, `hostWallGuardMs`, `cleanupGuardMs`, `combinedOutputBytes`, `artifactOracleSha256`, `reviewRecordSha256`, and `environment`. `host.platform` is `windows-x86_64`, with additional actual host metadata. `tools` contains exactly `helper`, `cli`, and `node`; each and `operatorAdmission` is an explicit `{path, bytes, sha256}` pin. Paths are normalized local drive-absolute Windows paths through private regular-file ancestors compatible with the existing `readSafe` portable-component policy. The bound Node must be the collector's actual interpreter. Environment entries are explicit and bounded; no inherited credential environment is forwarded.

Before using the real adapter, the operator supplies a canonical JSON admission record at the pinned absolute path. Its exact fields are `format: "zryna.cli-performance-windows-operator-binding.v1"`, `tools`, `helperBuiltFromSha256`, `sourceCommit`, `sourceTree`, `catalogueSha256`, `artifactOracleSha256`, and `reviewRecordSha256`. Every field binds the capture record; `helperBuiltFromSha256` must equal the frozen existing helper source-pin record SHA-256 `ea0a832ad83b3d6473c99a359da96fb5f7a1587d1c76254f12e4a9dbeb188e3a`. The collector verifies all 29 exact helper/calibration files, the source-pin record, admission record and tools, then retains their persistent file identities for checks before and after each command, including failed commands. This record binds operator inputs; it does not prove a build or grant source/host/baseline authority. No admission booleans or arbitrary workload flags exist.

Correctness oracles must be qualified and frozen independently before collection. The canonical array's hash is bound in both capture and operator admission. It has exactly the 20 ordered selectors, each with `selector`, `manifest`, exact public `stdout` and `stderr` strings, and the full sorted unique owned artifact `files` inventory of `{path, bytes, sha256}` pins including the manifest. The exact stdout must decode to the current original typed expected response. The collector checks all artifacts and both streams on every attempt, and removes only that verified owned bundle. It creates the M3 stage exclusively, verifies the original closed import graph and copied bytes before and after commands, and removes the verified stage only after a complete round. Failed or partial stages and all evidence remain available for inspection.

The helper invocation is exactly `helper --timeout-ms GUARD --output FRESH_SAMPLE -- CLI FIXED_ARGV`. The helper owns the same measured no-breakaway Job with KILL_ON_JOB_CLOSE. It retains `result.json`, `stdout.raw`, and `stderr.raw` in its create-only sample directory. Node retains the outer helper outcome/streams and copies of all readable helper bytes before parsing or asserting observation validity. Original helper files are retained even when reading one exceeds a bound. The existing strict `flat`, `helperKeys`, and `helperTypes` parser is reused. Nonzero exit, timeout, overflow, spawn failure, forced termination, unknown EOF, missing main exit, incomplete cleanup, a nonempty Job, failed peak query, invalid metadata or any correctness/material drift invalidates the whole round. There is no fallback to a taskkill-only success path. The child stream cap remains 16 MiB; cleanup reserve remains 10 seconds; the reviewed host guard is positive and at most 900000 ms. The outer Node guard adds only the helper's 10-second cleanup reserve and a 1-second reporting margin; an outer timeout remains invalid because closure is unknown.

Windows memory is the helper's actual `PeakJobMemoryUsed` committed-byte value. It is never relabeled as RSS, working set or summed process peaks. QPC start/end/frequency/delta remain canonical unsigned64 decimal strings, including values above JavaScript Number precision. The collector checks exact delta arithmetic and guard consistency. Five-observation summaries retain tick medians/maxima plus their frequency and represent normalized spread as an exact numerator/denominator pair. No floating-point wall conversion or rounding claim is introduced.

Every resulting session keeps `sourceAuthenticated: false`, `performanceQualified: false`, `baselineAuthority: null`, `thresholds: null`, and `closureStatus: "blocked"`. A debug CLI may qualify IO only. Baseline/held-out round labels never issue baseline authority.
